Phase 0: Setup & Prerequisites

⏱️ 15 minutes

Step 0.1: Launch EC2 Instance

PURPOSE:
  • Need a server to run Docker and push images to AWS
  • EC2 instance will be your deployment machine
    • HOW TO DO:
  • Go to: AWS Console → EC2 → Instances
  • Click: "Launch Instances"
  • Select: Ubuntu 22.04 LTS
  • Instance type: t3.medium (or larger)
  • Storage: 30GB
  • Create security group allowing SSH (port 22)
  • Launch and SSH in: ssh -i your-key.pem ec2-user@your-ec2-ip

    • Step 0.2: Run Setup Script (Installs All Tools)

    PURPOSE:

    Automated setup installs all required tools for deployment

    📁 File Location: railway-microapps/setup.sh
    WHAT INSTALLS:
  • ✅ AWS CLI v2 (AWS command line tool)
  • ✅ Docker (container runtime)
  • ✅ kubectl (Kubernetes client)
  • ✅ git (version control)
  • ✅ curl (HTTP client)
    • HOW TO RUN:
    # Option 1: Download and run from repo git clone https://github.com/devopsmate7/railway-microapps.git cd railway-microapps bash setup.sh # Option 2: Run directly from terminal (if setup.sh is available) bash setup.sh
    The script will automatically verify all installations!

    Step 0.3: Configure AWS Credentials

    aws configure # Enter: # AWS Access Key ID: [your-key] # AWS Secret Access Key: [your-secret] # Default region: ap-south-1 # Default output: json

    Phase 1: Networking (VPC, Subnets, Routes)

    ⏱️ 5 minutes
    🎯 WHAT WE'RE DOING: Building AWS network foundation for the microservices

    Step 1.1: Create VPC

    PURPOSE:

    VPC = Your isolated network in AWS (like your own private cloud)

    HOW TO DO:
  • AWS Console → VPC → Your VPCs
  • Click: "Create VPC"
  • Name: railway-vpc
  • IPv4 CIDR: 10.0.0.0/16
  • Click: "Create VPC"
  • ✅ SAVE: Copy VPC ID (vpc-xxxxx)

    • Step 1.2: Create Public & Private Subnets

    PURPOSE:
  • Public subnets: NAT Gateway, Load Balancers (reach internet)
  • Private subnets: EKS worker nodes (hidden but can reach internet)
    • CREATE PUBLIC SUBNETS:
  • Go to: VPC → Subnets → "Create subnet"
  • Subnet 1: railway-public-1a, CIDR: 10.0.1.0/24, AZ: ap-south-1a
  • Subnet 2: railway-public-1b, CIDR: 10.0.2.0/24, AZ: ap-south-1b
  • Enable auto-assign public IP for both
    • CREATE PRIVATE SUBNETS:
  • Subnet 3: railway-private-1a, CIDR: 10.0.10.0/24, AZ: ap-south-1a
  • Subnet 4: railway-private-1b, CIDR: 10.0.11.0/24, AZ: ap-south-1b
  • DO NOT enable auto-assign public IP

    • Step 1.3: Enable DNS Hostnames & Resolution

    PURPOSE:

    Enable DNS so services can reach each other by name

    HOW TO DO:
  • AWS Console → VPC → Your VPCs
  • Select: railway-vpc
  • At bottom: Actions → Edit DNS hostnames
  • Enable: ✓ Enable DNS hostnames
  • Click: Save changes
  • Back: Actions → Edit DNS resolution
  • Enable: ✓ Enable DNS resolution
  • Click: Save changes

    • Step 1.4: Create Internet Gateway (IGW)

    PURPOSE:

    IGW connects your VPC to the internet

    HOW TO DO:
  • AWS Console → VPC → Internet Gateways
  • Click: "Create internet gateway" (orange button)
  • Name tag: railway-igw
  • Click: "Create internet gateway"
  • Attach to your VPC:
    • Actions → Attach to VPC
    • Select: railway-vpc
    • Click: "Attach internet gateway"
  • SAVE: Copy IGW ID (starts with igw-)

    • Step 1.5: Create Elastic IP (for NAT Gateway)

    PURPOSE:

    NAT Gateway needs a static public IP

    HOW TO DO:
  • EC2 → Elastic IPs
  • Click: "Allocate Elastic IP address"
  • Select pool: Amazon's IP address pool
  • Click: "Allocate"
  • SAVE: Copy Allocation ID (starts with eipalloc-)

    • Step 1.6: Create NAT Gateway

    PURPOSE:

    Private subnets can reach the internet for updates/downloads

    HOW TO DO:
  • AWS Console → VPC → NAT Gateways
  • Click: "Create NAT gateway"
  • Subnet: railway-public-1a (must be a public subnet)
  • Elastic IP allocation ID: choose your saved eipalloc-...
  • Click: "Create NAT gateway"
  • WAIT: Status goes from Pending → Available (2-3 min)
  • SAVE: NAT Gateway ID (starts with nat-)

    • Step 1.7: Create Public Route Table (Route to IGW)

    PURPOSE:

    Controls where public-subnet traffic goes

    HOW TO DO:
  • VPC → Route Tables
  • Click: "Create route table"
  • Name: railway-public-rt
  • VPC: railway-vpc
  • Click: "Create route table"
  • Open tab: Routes → Edit routes
  • Click: "Add route"
  • Route to add:
    • Destination: 0.0.0.0/0
    • Target: Internet Gateway → railway-igw
  • Click: "Save changes"
    • ASSOCIATE WITH PUBLIC SUBNETS:
  • Back in route table → Subnet associations
  • Click: "Edit subnet associations"
  • Select: railway-public-1a and railway-public-1b
  • Click: "Save associations"

    • Step 1.8: Create Private Route Table (Route to NAT)

    PURPOSE:

    Controls where private-subnet traffic goes (to NAT, not directly to IGW)

    HOW TO DO:
  • VPC → Route Tables
  • Click: "Create route table"
  • Name: railway-private-rt
  • VPC: railway-vpc
  • Click: "Create route table"
  • Open tab: Routes → Edit routes
  • Click: "Add route"
  • Route to add:
    • Destination: 0.0.0.0/0
    • Target: NAT Gateway → railway-nat
  • Click: "Save changes"
    • ASSOCIATE WITH PRIVATE SUBNETS:
  • Back in route table → Subnet associations
  • Click: "Edit subnet associations"
  • Select: railway-private-1a and railway-private-1b
  • Click: "Save associations"

    • Step 1.9: Create Security Group (Firewall)

    PURPOSE:

    Security Group controls allowed traffic (acts like a firewall)

    HOW TO DO:
  • EC2 → Security Groups
  • Click: "Create security group"
  • Name: railway-eks-sg
  • Description: Railway EKS security group
  • VPC: railway-vpc
  • Click: "Create security group"
  • Open tab: Inbound rules
  • Click: "Edit inbound rules"
  • Click: "Add rule"
  • Inbound rule:
    • Type: All traffic
    • Source: Custom → railway-eks-sg
  • Click: "Save rules"
    • ✅ Phase 1 Complete: VPC + DNS + IGW + NAT + Route Tables + Security Group ready!

    Phase 2: ECR Repositories & DynamoDB

    ⏱️ 5 minutes

    Step 2.1: Create ECR Repositories

    WHAT:

    Docker image storage for our 3 microservices

    REPO NAMES (from railway-microapps/services/):
    railway-dev/frontend
    railway-dev/train-service
    railway-dev/booking-service
    HOW TO DO:
  • AWS Console → ECR → Repositories
  • Click: "Create repository"
  • Create 3 repositories (one for each service above)
  • Enable: Scan on push, Tag immutability

    • Step 2.2: Create DynamoDB Table

    WHAT:

    Database to store train bookings

    📁 Path: Not in repo (created on AWS)
    HOW TO DO:
  • AWS Console → DynamoDB → Tables
  • Click: "Create table"
  • Table name: railway-dev-bookings
  • Partition key: pnr (String type)
  • Billing mode: Pay per request
    • ✅ Phase 2 Complete: ECR repos and database ready!

    Phase 3: IAM Roles

    ⏱️ 5 minutes
    ⚠️ Create 3 IAM roles with specific permissions

    Step 3.1-3.3: Create IAM Roles

    Role 1: EKS Cluster Role
  • Go to: IAM → Roles → "Create role"
  • Service: EKS → EKS - Cluster
  • Name: railway-eks-cluster-role
  • ✅ SAVE: Copy Role ARN
    • Role 2: EKS Node Role
  • Service: EC2
  • Add policies:
    AmazonEKSWorkerNodePolicy
    AmazonEKS_CNI_Policy
    AmazonEC2ContainerRegistryReadOnly
  • Name: railway-eks-node-role
  • ✅ SAVE: Copy Role ARN
    • Role 3: Booking Service Pod Identity Role
  • Service: Pod → EKS - Pod Identity
  • Name: railway-booking-service-role
  • Attach DynamoDB read/write policy
  • ✅ SAVE: Copy Role ARN
    • ✅ Phase 3 Complete: 3 IAM roles created!

    Phase 4: Create EKS Cluster

    ⏱️ 20 minutes (mostly waiting)

    Step 4.1: Create EKS Cluster

    HOW TO DO:
  • AWS Console → EKS → Clusters
  • Click: "Create cluster"
  • Choose configuration: Custom configuration
  • Cluster name: railway-dev
  • Cluster IAM role: railway-eks-cluster-role
  • Kubernetes version: 1.29
  • Compute option: choose EC2 Managed Node Groups (do NOT use EKS Auto Mode)
  • Node IAM role: railway-eks-node-role
  • Next → Specify networking:
    • VPC: railway-vpc
    • Subnets: select all 4 (railway-public-1a, railway-public-1b, railway-private-1a, railway-private-1b)
    • Security group: railway-eks-sg
  • Next → Configure observability: leave defaults
  • Next → Select add-ons: leave defaults (recommended) and keep the standard EKS add-ons
  • Review → Create
  • ⏳ WAIT: 10-15 minutes for cluster to be Active

    • Step 4.2: Create Node Group (Worker Nodes)

    HOW TO DO:
  • Go to: EKS → Clusters → railway-dev
  • Click: "Compute" tab
  • Click: "Create node group"
  • Name: railway-nodes
  • Node IAM role: railway-eks-node-role
  • Instance type: t3.medium
  • Size / Auto scaling: min=1, max=3, desired=2
  • Subnets: select private subnets only (railway-private-1a, railway-private-1b)
  • ⏳ WAIT: 5-10 minutes for nodes to be Active / Ready
    • ✅ Phase 4 Complete: EKS cluster with 2 worker nodes!

    Phase 5: Build & Push Docker Images

    ⏱️ 15 minutes

    Step 5.1-5.3: Build & Push Images

    STEP 1: Login to EC2 and navigate to repo:
    cd railway-microapps
    STEP 2: Get Account ID:
    # Replace YOUR_AWS_ACCOUNT_ID with your student AWS Account ID (12 digits)
    STEP 3: Login to ECR:
    aws ecr get-login-password --region ap-southeast-2 | docker login --username AWS --password-stdin YOUR_AWS_ACCOUNT_ID.dkr.ecr.ap-southeast-2.amazonaws.com
    STEP 4: Build Frontend Image (from services/frontend/):
    docker build -t railway-dev/frontend:v1.0 services/frontend/ docker tag railway-dev/frontend:v1.0 YOUR_AWS_ACCOUNT_ID.dkr.ecr.ap-southeast-2.amazonaws.com/railway-dev/frontend:v1.0 docker push YOUR_AWS_ACCOUNT_ID.dkr.ecr.ap-southeast-2.amazonaws.com/railway-dev/frontend:v1.0
    STEP 5: Build Train-Service (from services/train-service/):
    docker build -t railway-dev/train-service:v1.0 services/train-service/ docker tag railway-dev/train-service:v1.0 YOUR_AWS_ACCOUNT_ID.dkr.ecr.ap-southeast-2.amazonaws.com/railway-dev/train-service:v1.0 docker push YOUR_AWS_ACCOUNT_ID.dkr.ecr.ap-southeast-2.amazonaws.com/railway-dev/train-service:v1.0
    STEP 6: Build Booking-Service (from services/booking-service/):
    docker build -t railway-dev/booking-service:v1.0 services/booking-service/ docker tag railway-dev/booking-service:v1.0 YOUR_AWS_ACCOUNT_ID.dkr.ecr.ap-southeast-2.amazonaws.com/railway-dev/booking-service:v1.0 docker push YOUR_AWS_ACCOUNT_ID.dkr.ecr.ap-southeast-2.amazonaws.com/railway-dev/booking-service:v1.0
    ✅ Phase 5 Complete: All 3 images in ECR!

    Phase 6: Deploy to Kubernetes

    ⏱️ 10 minutes

    Step 6.1: Connect kubectl to Cluster

    aws eks update-kubeconfig --region ap-southeast-2 --name railway-dev kubectl get nodes # Verify connection (should show 2 nodes)

    Step 6.2: Deploy Services using Kubernetes Manifests

    DEPLOY NAMESPACE (from deploy/k8s/base/namespace.yaml):
    kubectl apply -f deploy/k8s/base/namespace.yaml
    DEPLOY TRAIN-SERVICE (from deploy/k8s/base/train-service.yaml):
    kubectl apply -f deploy/k8s/base/train-service.yaml -n railway
    DEPLOY BOOKING-SERVICE (from deploy/k8s/base/booking-service.yaml):
    kubectl apply -f deploy/k8s/base/booking-service.yaml -n railway
    DEPLOY FRONTEND (from deploy/k8s/base/frontend.yaml):
    kubectl apply -f deploy/k8s/base/frontend.yaml -n railway
    VERIFY DEPLOYMENT:
    kubectl get pods -n railway # Should show 3 pods running kubectl get svc -n railway # Should show LoadBalancer for frontend
    ✅ Phase 6 Complete: All services deployed to EKS!

    Phase 7: Install Argo CD (GitOps)

    ⏱️ 5 minutes

    Step 7.1: Install Argo CD

    kubectl create namespace argocd kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml kubectl wait --for=condition=Ready pod -l app.kubernetes.io/name=argocd-server -n argocd --timeout=300s

    Step 7.2: Get Argo CD Admin Password

    PURPOSE:

    Login to Argo CD web dashboard

    kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}" | base64 -d; echo
    📌 Note: Save this password! You'll need it to login.

    Step 7.3: Access Argo CD UI

    PURPOSE:

    View Argo CD dashboard to see GitOps deployments

    HOW:
    # Port forward to access the UI kubectl port-forward svc/argocd-server -n argocd 8443:443 & # Open in browser https://localhost:8443 # Login with: # Username: admin # Password: (from Step 7.2 above)
    🌐 Access: https://localhost:8443
    👤 Username: admin
    🔑 Password: From Step 7.2

    Step 7.4: Deploy Argo CD Application (from deploy/argocd/railway-dev.yaml)

    PURPOSE:

    Tell Argo CD to watch Git and auto-deploy changes

    kubectl apply -f deploy/argocd/railway-dev.yaml -n argocd
    THEN IN ARGO UI:
  • ✅ Go to Applications (left menu)
  • ✅ You should see "railway-dev" application
  • ✅ It shows services deployed from Git
  • ✅ Green = synced, Red = out of sync
    • ✅ Phase 7 Complete: Argo CD UI accessible & watching Git!
